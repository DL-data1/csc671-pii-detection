The full baseline model showed a large improvement over the small checkpoint, especially for USERNAME and URL_PERSONAL.

- USERNAME: weak / often missed or classified as EMAIL
- URL_PERSONAL: usually missed
- EMAIL: some misses
- PHONE_NUM: generally better on the small example set

Full baseline:
- USERNAME: detected correctly in the tested examples
- URL_PERSONAL: detected correctly in the tested examples
- EMAIL: detected correctly in the tested examples
- PHONE_NUM: still weak for unseen US-style phone formats

Notes
-----
- The inference pipeline works with the full baseline checkpoint.
- Highlighted text, JSON output, redaction, and sliding-window inference are working.
- Long documents are processed using overlapping 512-subword windows with a 128-subword overlap.
- The current inference implementation averages word logits across overlapping windows to match the training and validation procedure.
- The full baseline is the current best checkpoint, but it may be replaced by a later tuned model.
- All prompt templates appear across train, validation, and test, so the reported performance mainly reflects in-template performance rather than fully unseen-template generalization.
